# 程式架構說明

最後更新：2026-10-27

這份文件說明目前 C# 程式與 Shader 怎麼分工、資料怎麼流動，以及之後可以調整的地方。
每個功能的細節請看各自的說明文件（索引在 [專案結構.md](專案結構.md) 第 2 節）。

---

## 1. 分層

```
┌─ 資料 ───────────────────────────────────────────────────────────────┐
│  Resources/Planets.csv ──► PlanetSpec.ParseCsv()  一列 = 一顆天體       │
└──────────────────────────────────────────────────────────────────────┘
                 │
┌─ 建立（Awake 一次）──────────────────────────────────────────────────┐
│  SolarSystemBuilder                                                  │
│   ├─ 軌道初始條件（物理）：近日點、vis-viva、疊加 parent、週期           │
│   ├─ 外觀（畫面）：Prefab 或純色球、TrailRenderer、BodySpin、SunVisual  │
│   ├─ 環境（畫面）：掛 SpaceEnvironment                                 │
│   └─ RemoveCenterOfMassDrift() → simulator.Initialize()              │
└──────────────────────────────────────────────────────────────────────┘
                 │
┌─ 物理（每幀 Update）─────────────────────────────────────────────────┐
│  NBodySimulator ◄──► CelestialBody × 29（mass、position、velocity）   │
│   ├─ Step()：Velocity Verlet，O(N²) 重力                              │
│   ├─ SimulatedDays：累積的模擬時間                                     │
│   └─ SyncTransforms()：AU → Unity 單位，衛星距離 × orbitScale（畫面）  │
└──────────────────────────────────────────────────────────────────────┘
                 │ Transform.position
┌─ 畫面（只影響畫面，每個都有開關）──────────────────────────────────────┐
│  SunVisual          太陽外觀、Bloom；每幀設定全域 _StarrySkySunPos ─┐   │
│  BodySpin           依 SimulatedDays 的差值自轉                    │   │
│  SpaceEnvironment   星空天空盒、背景、環境光、關 Directional Light   │   │
│  Shader：Planet / Earth / SimpleBody / PlanetRing ◄── 光的方向 ───┘   │
│          SunSurface / SunCorona / Starfield                          │
└──────────────────────────────────────────────────────────────────────┘
┌─ 操作與 UI（IMGUI）──────────────────────────────────────────────────┐
│  TimeControlUI   改 simulator.daysPerSecond；暫停用 Time.timeScale = 0 │
│  CameraFocus     天體列表、視角面板、軌道相機（控制 Main Camera）       │
└──────────────────────────────────────────────────────────────────────┘
```

**原則**：物理只用 `Vec3d`（double）、單位是 AU / 太陽質量 / 天；畫面元件只讀物理結果，從不改物理狀態。

## 2. 每個類別的責任

| 類別 | 層 | 讀誰 | 寫誰 | 行數 |
| --- | --- | --- | --- | --- |
| `PlanetSpec` | 資料 | CSV 文字 | — | 79 |
| `SolarSystemBuilder` | 建立 | `PlanetSpec`、Resources 裡的 Prefab / 材質 | 建立所有天體 GameObject、`simulator.bodies` | 179 |
| `CelestialBody` | 物理 | — | （被 NBodySimulator 讀寫） | 30 |
| `NBodySimulator` | 物理 | `CelestialBody` | `CelestialBody` 狀態、`Transform.position` | 184 |
| `SunVisual` | 畫面 | 太陽 Transform | 材質、Bloom Volume、全域 `_StarrySkySunPos` | 122 |
| `BodySpin` | 畫面 | `simulator.SimulatedDays`、`builder.addSpin` / `maxSpinDaysPerSecond` | 自己的 `Transform.rotation` | 45 |
| `SpaceEnvironment` | 畫面 | — | `RenderSettings`、`Camera.main`、Directional Light | 71 |
| `TimeControlUI` | 操作 | `simulator.SimulatedDays` | `simulator.daysPerSecond`、`Time.timeScale` | 122 |
| `CameraFocus` | 操作 | `simulator.bodies`、天體 Transform | Main Camera 的位置、方向、視野、clip | 381 |

## 3. 一幀裡發生的事（執行順序）

| 階段 | 元件 | 為什麼放這裡 |
| --- | --- | --- |
| `Update` | `TimeControlUI`、`CameraFocus` | 讀輸入 |
| `Update` | `NBodySimulator` | 推進物理、更新天體位置 |
| `Update` | `SolarSystemBuilder` | 依播放速度更新軌跡長度 |
| `LateUpdate` | `CameraFocus` | 天體這一幀已經移動完，相機才跟上，不會慢一幀 |
| `LateUpdate` | `SunVisual` | 太陽位置 → `_StarrySkySunPos` |
| `LateUpdate` | `BodySpin` | 物理已推進完這一幀的 `SimulatedDays` |
| `LateUpdate` | `SpaceEnvironment` | 套用 Inspector 的數值（Play 中可即時調） |
| `OnGUI` | `TimeControlUI`、`CameraFocus` | 畫面板 |

同一個階段裡，不同元件的先後順序 Unity 不保證。目前的寫法不依賴這個順序。

## 4. 元件之間怎麼溝通

| 方式 | 例子 | 優點 | 風險 |
| --- | --- | --- | --- |
| 直接引用 | `BodySpin.simulator`、`BodySpin.builder` | 簡單、看得到 | 元件互相知道對方，改一個可能要改另一個 |
| 全域 Shader 變數 | `Shader.SetGlobalVector("_StarrySkySunPos", …)` | 所有 Shader 都讀得到，不用逐個材質設定 | 誰設定、誰在讀，從程式看不出來 |
| 字串路徑 | `Resources.Load("Prefabs/Sun")`、`Shader.Find(...)` | 資料驅動，CSV 就能改 | 打錯字只會在執行時才發現 |
| 全域物件 | `Camera.main`、`RenderSettings`、`Time.timeScale` | 不用設定引用 | 影響整個場景 |

## 5. 做得好、建議保留的設計

- **物理 / 畫面分開**：外觀元件都不碰物理，各自有開關，關掉也不影響模擬結果。
- **double 精度**：物理用 `Vec3d`，畫面才轉 float。太陽系的距離範圍很大，float 不夠用。
- **資料驅動**：加天體、換外觀、改自轉都只改 CSV。
- **Shader 共用 `.cginc`**：光源方向、噪聲寫一次，所有 Shader 共用；全部 URP / Built-in 都能畫。
- **Unity 外驗證**：`nbody_check.py`（物理）、`sun_corona_preview.py`、`starfield_preview.py`（外觀）。

## 6. 可以調整的地方

依影響排序。第一階段風險低、外部行為不變；第二階段是結構重整。

### 第一階段

| # | 現況 | 問題 | 建議 |
| --- | --- | --- | --- |
| 1 | 光源 `_StarrySkySunPos` 由 `SunVisual`（太陽**外觀**）設定 | 太陽沒有 SunVisual 時（Sun Visual 不勾、又沒有 Prefab），所有行星的光會退回材質上的預覽方向 | 抽成獨立的 `SunLight` 元件，太陽一定會掛 |
| 2 | CSV 依欄位**順序**解析（`c[9]`、`c[10]`） | 在 Excel 插一欄或換順序，資料會讀錯但不報錯 | 依標題列的**欄位名稱**讀（和 `nbody_check.py` 的 `DictReader` 一樣），舊檔案照樣能讀 |
| 3 | `SunVisual`、`BodySpin`、`SpaceEnvironment` 是執行時才加的元件 | Play 中調好的數值停止後消失，只能記下來再改程式預設值 | 畫面設定集中到 **ScriptableObject** 資產（例如 `VisualSettings.asset`）。資產在 Play 中改的值會保留 |
| 9 | 小事 | — | `SunNoise.cginc` 已被星空共用，改名為共用噪聲；軌跡材質共用一個，不要每條 `new Material`；`FindObjectsOfType` 改新版 API |

### 第二階段

| # | 現況 | 問題 | 建議 |
| --- | --- | --- | --- |
| 4 | `SolarSystemBuilder` 同時負責資料、軌道公式、建立外觀、軌跡、自轉、環境 | 每個新功能都改到它；軌道公式無法單獨測試 | 拆成 `OrbitMath`（純公式的靜態方法）、`BodyFactory`（外觀、軌跡、自轉）；`SpaceEnvironment` 直接放在場景裡 |
| 5 | `NBodySimulator.SyncTransforms()` 裡有 `unityUnitsPerAU`、`orbitScale` | 物理類別裡混了「怎麼畫」 | 移到畫面層（例如 `BodyView`），模擬器只管 AU 和天 |
| 6 | `CameraFocus` 381 行：輸入、相機數學、兩個 IMGUI 面板 | 加視角或換 UI 都要動同一個檔案 | 拆成 `CameraRig`（視角、軌道相機）與 `BodyListUI`、`ViewPanelUI` |
| 7 | 時間：模擬器用 `daysPerSecond × deltaTime`，暫停用 `Time.timeScale`，軌跡、自轉各自換算 | 規則分散 | `SimulationClock`：播放速度、暫停、「這一幀推進了幾天」都從這裡讀 |

### 之後有需要再做

| # | 現況 | 建議 |
| --- | --- | --- |
| 8 | 物理狀態放在 MonoBehaviour（`CelestialBody.position`） | 純 C# 的 `NBodySystem`（陣列存狀態），MonoBehaviour 只做橋接；加 Unity Test Framework 的能量守恆測試，不用再靠 Python 版對照。天體數量變多時，陣列也比較快 |

## 7. 讀程式的建議順序

1. `PlanetSpec.cs` → `Planets.csv`：資料長什麼樣子。
2. `SolarSystemBuilder.Awake()`：天體怎麼被建立、初始速度怎麼算（搭配 [初始速度計算說明.md](初始速度計算說明.md)）。
3. `NBodySimulator.Update()` → `Step()` → `ComputeAccelerations()`：物理核心（搭配 [N-body太陽系模擬教學.md](N-body太陽系模擬教學.md)）。
4. `CameraFocus.ComputeView()`：相機數學（搭配 [視角切換說明.md](視角切換說明.md)）。
5. `PlanetLighting.cginc` → `SimpleBody.shader`：最短的 Shader，看懂光從太陽來的寫法，再看 `Planet.shader`。
