# 星空說明（程序化天空盒）

最後更新：2026-10-27

遠方原本是純黑的，現在換成一片程序化的星空：三層亮度不同的星星，加上一條和軌道面傾斜 60° 的銀河。
星空是**天空盒**，在無限遠，所以只會跟著相機的**方向**變，不會跟著位置變。切換視角時，就能看出相機到底朝哪裡看。

| 項目 | 原本 | 現在 |
| --- | --- | --- |
| 背景 | 純黑（`SpaceEnvironment` 的 Solid Color） | 星空天空盒 `StarrySky/Starfield` |
| 星星怎麼來的 | — | Shader 依方向即時算出，不用貼圖 |
| 望遠鏡（視野縮到 1°） | — | 星星仍是清楚的小點，不會變成模糊的大圓 |
| 開關 | — | `SpaceEnvironment > Starfield`，關掉就回到純黑 |

## 2. 不同視角看到什麼

| 視角 | 星空的樣子 |
| --- | --- |
| 俯視 | 看的是「軌道面的正上方」那一片天空；銀河斜斜地橫過畫面一角，或不在畫面裡 |
| 斜視 / 側視 | 地平線方向的天空；銀河會以一條斜帶出現 |
| 迎光 / 背光 | 隨著星球公轉，背景的星空跟著**轉動**（相機方向在變） |
| 從星球看出去 | 右鍵轉頭就像在看真的夜空；滾輪拉成望遠鏡時，星星還是清楚的小點，暗星也會變得比較容易看到 |
| 在不同星球之間切換 | 只要看的方向一樣，星空就**完全一樣**。從水星和海王星看，星星的位置沒有差別 |

最後一點是天空盒的關鍵：真實的星星離我們好幾光年，太陽系的大小（約 0.0005 光年）和它比起來可以忽略，
所以在太陽系裡走來走去，星星都不會移動。天空盒剛好就是這樣的東西。

## 3. 原理

### 3.1 天空盒在無限遠
天空盒是一個包住相機的大方塊，每幀都跟著相機移動，Unity 最先畫它（Queue = Background）、不寫深度，其他東西都畫在它前面。
Shader 只用到「這個像素朝哪個方向」：

```hlsl
o.dir = v.vertex.xyz;   // 天空盒網格的頂點位置就是方向
float3 d = normalize(i.dir);
```

### 3.2 把天空切成格子，每格最多一顆星
要在天空中撒星星，而且每次看都在同一個位置：

1. **方向 → 立方體的面**：看方向的哪個分量最大（例如 x 最大就是 ±x 面），把另外兩個分量除以它，得到那一面上的座標 uv（−1 ~ 1）。
   這就是 cube map 的原理，和「把地球攤成 6 面的骰子」一樣。
2. **每一面切成 N × N 格**，格子編號 `id = floor(uv × N)`。
3. 用格子編號做 **hash**（偽隨機數）：決定這格有沒有星星、星星在格子裡的哪裡、多亮、什麼顏色。
   同一格永遠得到同一組數字，所以星星不會跳動。
4. 星星只放在格子**中間 60%** 的範圍，離格線留空，光點才不會被切掉一半。

三層格子疏密不同：

| 層 | 每面格數 | 有星星的比例 | 亮度 | 約幾顆 |
| --- | --- | --- | --- | --- |
| 亮星 | 40 × 40 | 8% | 0.3 ~ 1.4（少數超過 1，會被 Bloom 抓到） | 770 |
| 中等 | 110 × 110 | 20% | 0.08 ~ 0.45 | 14,500 |
| 暗星 | 200 × 200 | 10% ~ 50%（銀河裡比較多） | 0.02 ~ 0.12 | 約 4 萬 |

亮度用 `pow(隨機數, 6)` 分佈：大多數星星很暗，只有少數很亮，和真實星空一樣。
顏色代表恆星的表面溫度：橘紅（低溫）15%、黃白 20%、白 50%、藍白（高溫）15%。

### 3.3 星星大小 = 幾個像素，而不是幾度
如果星星的大小用固定的角度，視野縮小（望遠鏡）時星星會被放大成模糊的圓，視野放大時又會小到消失、一閃一閃。
所以改用「一個像素對應幾度」：

```hlsl
float pixelAngle = 2.0 / (unity_CameraProjection._m11 * _ScreenParams.y);   // _m11 = 1 / tan(視野/2)
float sigma = pixelAngle * _StarSize;                                        // 預設 0.6 個像素
float shape = exp(-ang * ang / (2 * sigma * sigma));                         // 高斯光點
```

真實的星星離我們太遠，看起來永遠是一個點，不管用多大的望遠鏡都一樣。這個寫法剛好符合這一點。
這也是不用貼圖的原因：貼圖的解析度固定，放大就糊了。

### 3.4 銀河
銀河是一條繞著整個天空的帶子。用銀河面的法線（**銀極**）算出每個方向「離銀河面多遠」：

```hlsl
float lat  = dot(d, pole);                        // sin(銀緯)，0 = 在銀河面上
float band = exp(-lat * lat / (2 * 0.12 * 0.12)); // 高斯帶，寬約 ±7°
```

再疊上：

| 成分 | 做法 | 效果 |
| --- | --- | --- |
| 星雲 | fBm 噪聲（`sunFbmOct`，和太陽共用） | 一團一團、不均勻 |
| 銀河中心 | 某個方向附近的高斯亮斑，偏黃 | 人馬座方向特別亮 |
| 暗塵帶 | 另一層噪聲，只在銀河正中央把亮度壓暗 | 中間一條黑色的裂縫 |
| 暗星密度 | 暗星層的比例 × (0.4 + 1.6 × band) | 銀河裡的星星比較密 |

真實的銀河面和地球軌道面（黃道）夾約 60°，所以預設 `_GalacticTilt = 60`。

### 3.5 亮度很節制
| 量 | 預覽腳本的結果 |
| --- | --- |
| 最亮的星 | HDR 1.38 |
| 超過 1（會被 Bloom 抓到）的像素 | 0.003% |
| 銀河最亮 | 0.076 |
| 整片天空平均 | 0.008 |

背景要很暗，行星和太陽才是畫面的主角。只有最亮的幾十顆星會有一點點 Bloom 光暈。

## 4. 可調參數

### Play 中：Simulator > SpaceEnvironment > 星空
| 參數 | 預設 | 說明 |
| --- | --- | --- |
| Starfield | 開 | 關掉 = 純色背景（Background Color） |
| Star Brightness | 1 | 星星與銀河的整體亮度 |
| Milky Way | 1 | 銀河亮度，0 = 關 |

### 材質 `Resources/Materials/Starfield.mat`（不按 Play 改，會存進檔案）
| 參數 | 預設 | 越大會怎樣 |
| --- | --- | --- |
| 星星數量 | 1 | 星星越多 |
| 星星大小（像素） | 0.6 | 星星越大；太小（< 0.4）時鏡頭轉動會一閃一閃 |
| 銀河面和軌道面的夾角 | 60 | 0 = 銀河和軌道面重疊，90 = 垂直 |

Play 中 `SpaceEnvironment` 用的是複製出來的材質，所以要改材質參數請在 Play 之外改材質檔。

**想在編輯模式也看到星空**：Window > Rendering > Lighting > Environment，Skybox Material 指定 `Starfield`；
Main Camera 的 Background Type 改成 Skybox。然後 **Ctrl + S** 存場景。

## 5. 在 Unity 外預覽

```
python Assets/Docs/starfield_preview.py [輸出資料夾，預設 Temp/StarrySkyPreview]
```

輸出三張圖（約 20 秒）：

- `starfield_equirect.png`：全天空攤平（2:1）。上下兩邊的星星被拉成橫線，這是攤平投影造成的，遊戲裡不會這樣。
- `starfield_center.png`：60° 視野看向銀河中心，像素大小和 1080p 遊戲畫面相同。
- `starfield_plane.png`：看向軌道面方向。

## 6. 已知限制與下一步

- **尚未在 Unity 中確認**：Shader 只能在 Unity 裡編譯。
- 星星是隨機的，不是真實星座。之後可以用真實星表（例如 Yale Bright Star Catalog 的約 9000 顆亮星）產生資料。
- 立方體 6 個面的角落附近，格子的實際角度比較小，星星會稍微密一點（看不太出來）。
- 天空盒不受 Bloom 以外的效果影響；星星不會閃爍（真實的閃爍是大氣造成的，太空中本來就不閃）。
- 每個像素要算 3 層星星 + 9 層噪聲，全螢幕都是天空時比一般背景吃 GPU，但仍比體積日冕輕很多。
