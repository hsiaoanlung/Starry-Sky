# 初始速度計算說明

說明 `SolarSystemBuilder` 在 t = 0 時，如何從 `Planets.csv` 的軌道參數（`a`、`e`、`mass`、`parent`）算出每顆天體的初始位置與速度。
欄位定義見 [Planets.csv欄位說明.md](Planets.csv欄位說明.md)，背後的物理見 [N-body太陽系模擬教學.md](N-body太陽系模擬教學.md) 第 6 節。

整個流程分四步：

1. 把天體放在相對 `parent` 的近日點。
2. 用 vis-viva 方程式算出近日點速度大小。
3. 疊加 `parent` 本身的位置與速度。
4. 全部建立完後，把系統總動量歸零。

單位：距離 AU、質量 太陽質量、時間 天，$G = 2.959122082855911 \times 10^{-4}\ \mathrm{AU^3 / (M_\odot \cdot day^2)}$。

---

## 1. 從近日點出發

每顆天體在 t = 0 時放在軌道上距離 `parent` **最近**的點，也就是近日點（繞地球時叫近地點）：

$$r_p = a(1-e)$$

選近日點的理由：

- 在近日點（以及遠日點），速度方向剛好**垂直**於與 `parent` 的連線，不必另外算角度。
- 速度大小有簡單的封閉公式（第 2 節）。

程式中：

- 位置放在 `parent` 的 **+x** 方向，距離 $r_p$。
- 速度方向沿 **+z**。

軌道面是 XZ 平面。相機從 +y 往下看時，畫面右方是 +x、上方是 +z，所以天體是**逆時針**公轉，與真實太陽系從北方俯視的方向一致。

CSV 中 `retrograde = 1` 的天體（例如海衛一 Triton）速度改沿 **-z**，變成順時針逆行，速度大小不變。

---

## 2. 速度大小：vis-viva 方程式

### 2.1 公式

二體問題中，橢圓軌道上任一點的速度大小由**活力公式（vis-viva equation）**決定：

$$v^2 = \mu\left(\frac{2}{r} - \frac{1}{a}\right), \qquad \mu = G\,(M_{parent} + m)$$

- $r$：當下與 `parent` 的距離
- $a$：半長軸
- $\mu$：重力參數

### 2.2 代入近日點

把 $r = r_p = a(1-e)$ 代入括號：

$$\frac{2}{a(1-e)} - \frac{1}{a}
= \frac{2 - (1-e)}{a(1-e)}
= \frac{1+e}{a(1-e)}
= \frac{1+e}{r_p}$$

所以近日點速度為：

$$\boxed{\ v_p = \sqrt{\frac{\mu\,(1+e)}{r_p}}\ }$$

### 2.3 直觀理解

- **e = 0（正圓）**：$r_p = a$，公式變成 $v = \sqrt{\mu / r}$，就是圓周運動所需速度（重力 = 向心力）。
- **e > 0**：近日點速度比同距離的圓軌道速度快 $\sqrt{1+e}$ 倍，天體會被「甩」出去，形成橢圓，在遠日點 $r_a = a(1+e)$ 減到最慢。
- **e → 1**：速度趨近逃逸速度 $\sqrt{2\mu / r_p}$，軌道越來越扁長。

### 2.4 為什麼 μ 是 G(M + m) 而不是 GM

兩顆天體其實是**繞著共同質心**轉，而不是小的繞著固定不動的大的轉。
把問題改寫成「相對運動」時，等效的重力參數是兩者質量和：

$$\ddot{\vec r}_{rel} = -\frac{G(M+m)}{|\vec r_{rel}|^3}\,\vec r_{rel}$$

- 行星對太陽：$m/M$ 最大是木星的約 0.1%，差異很小。
- 月球對地球：$m/M \approx 1.2\%$，就不能忽略。若用 $GM$，月球初速會偏慢約 0.6%，軌道離心率會跟設定值不同。

## 3. 疊加 parent 的位置與速度

第 1、2 節算出的是**相對 `parent`** 的狀態。月球還要跟著地球一起繞太陽，所以實際的初始狀態是：

$$\vec r = \vec r_{parent} + (r_p,\ 0,\ 0)$$

$$\vec v = \vec v_{parent} + (0,\ 0,\ v_p)$$

- 太陽在原點靜止，所以行星疊加的是零向量。
- 月球疊加的是地球的位置與速度（約 30 km/s），月球相對地球的 1 km/s 是額外加上去的。
- 這就是 `parent` 必須在 CSV 中排在前面的原因：建立月球時，地球的狀態必須已經算好。

---

## 4. 總動量歸零

全部天體建立完之後，`NBodySimulator.RemoveCenterOfMassDrift()` 會把每顆天體的速度減去質心速度，位置減去質心位置：

$$\vec v_{cm} = \frac{\sum_i m_i \vec v_i}{\sum_i m_i}, \qquad
\vec r_{cm} = \frac{\sum_i m_i \vec r_i}{\sum_i m_i}$$

$$\vec v_i \leftarrow \vec v_i - \vec v_{cm}, \qquad \vec r_i \leftarrow \vec r_i - \vec r_{cm}$$

**為什麼需要：**
第 3 節的做法讓太陽靜止、所有行星都往 +z 跑，系統總動量不為零。不修正的話，整個太陽系（含太陽）會一起朝 +z 慢慢漂走，最後跑出相機畫面。

**為什麼不會破壞軌道：**
所有天體減去**同一個**向量，彼此之間的相對位置與相對速度完全不變，而重力只取決於相對位置，所以軌道形狀不受影響，只是參考座標換成了質心座標。

**修正量多大：**
主要由木星貢獻，大約 $7.5 \times 10^{-6}$ AU/天（約 13 m/s）。修正後太陽會有一個很小的反向速度，這是真實的物理現象：太陽本來就繞著太陽系質心擺動。

## 5. 數值驗算

換算：1 AU/天 = 1.496×10⁸ km ÷ 86400 s ≈ 1731 km/s。

| | 地球（parent = Sun） | 月球（parent = Earth） |
| --- | --- | --- |
| $M_{parent} + m$ | 1 + 3.00×10⁻⁶ | 3.00×10⁻⁶ + 3.69×10⁻⁸ |
| $\mu$ | 2.959×10⁻⁴ | 8.987×10⁻¹⁰ |
| $a$, $e$ | 1 AU, 0.0167 | 0.00257 AU, 0.0549 |
| $r_p = a(1-e)$ | 0.9833 AU | 0.002429 AU（約 36.3 萬 km） |
| $v_p$ | 0.017492 AU/天 | 0.000625 AU/天 |
| 換算 | **30.29 km/s** | **1.08 km/s** |
| 真實值 | 近日點約 30.29 km/s | 近地點約 1.08 km/s |

兩者都與真實數據吻合。

用相同初始條件、Velocity Verlet、dt = 0.05 天模擬 2 年的結果：

- 月地距離維持在 0.00243 ~ 0.00265 AU，月球穩定繞地球。
- 相對能量誤差 $|\Delta E / E| \approx 6.5 \times 10^{-9}$。

## 6. 對應程式碼

`Assets/Script/N-body/SolarSystemBuilder.cs` 的 `Awake()`：

```csharp
// 沒有 parent（太陽）：放在原點靜止
if (string.IsNullOrEmpty(p.parent))
{
    created[p.name] = Create(p, Vec3d.zero, Vec3d.zero, null);
    continue;
}

// 第 2 節：近日點距離與速度
double mu = NBodySimulator.G * (parent.mass + p.mass);
double rp = p.a * (1.0 - p.e);
double vp = System.Math.Sqrt(mu * (1.0 + p.e) / rp);

// 第 1、3 節：放在 parent 的 +x，速度沿 +z，再疊加 parent 的狀態
created[p.name] = Create(p,
    parent.position + new Vec3d(rp, 0, 0),
    parent.velocity + new Vec3d(0, 0, vp),
    parent);

// ……所有天體建立完後
simulator.RemoveCenterOfMassDrift();   // 第 4 節
simulator.Initialize();
```

## 7. 限制

- **所有天體一開始排成一直線**（都在 +x 軸上），而且每條軌道的近日點都朝同一方向。真實太陽系的行星分散在各個角度，近日點方向也各不相同。
- **所有軌道都在同一平面**（XZ 平面），沒有軌道傾角。真實行星軌道有幾度的傾角，月球軌道對黃道傾斜約 5°。
- **初始速度是二體近似**：只考慮 `parent` 的重力，沒考慮其他天體。例如月球出發時還受太陽強烈影響，所以實際軌道會與 CSV 設定的 `a`、`e` 略有差異。這是真實的攝動，不是錯誤。

若需要真實的某一天的星體排列，可改用 NASA JPL Horizons 提供的位置與速度向量作為初始條件，取代本文的軌道參數推算。
