# 聲音合成入門教學

這份教學從零開始說明：聲音在電腦裡是什麼、怎麼用數學「算」出一段音樂，以及 Unity 怎麼播放聲音。
範例都取自 `space_music_gen.py`（背景音樂產生器），功能說明見 [背景音樂說明.md](背景音樂說明.md)。

---

## 1. 聲音是一串數字

聲音是空氣壓力的快速變化。麥克風把壓力變成電壓，電腦每秒量很多次，存成一串數字，這就是**取樣**。

| 名詞 | 意思 | 這個專案 |
| --- | --- | --- |
| 取樣率（sample rate） | 每秒量幾次 | 32000 Hz（CD 是 44100 Hz） |
| 取樣（sample） | 某一瞬間的壓力，範圍 -1 ~ 1 | 96 秒 × 32000 = 3,072,000 個 |
| 位元深度 | 每個取樣用幾個 bit 存 | 16 bit：-32768 ~ 32767 |
| 聲道 | 左右各一串 | 立體聲（2 聲道） |

**奈奎斯特定理**：取樣率最多只能表示**一半**頻率以下的聲音。32 kHz 可以表示到 16 kHz，背景音樂的內容大多在 5 kHz 以下，所以已經足夠，檔案還比 44.1 kHz 小 27%。

所以「合成聲音」就是：**寫一個函式 `x(t)`，在 t = 0, 1/SR, 2/SR, … 算出它的值**。

```python
SR = 32000
t = np.arange(N) / SR          # 每個取樣的時間（秒）
x = np.sin(2 * np.pi * 440 * t)  # 440 Hz 的正弦波 = A4（調音用的「La」）
```

## 2. 正弦波：頻率 = 音高、振幅 = 音量

最簡單的聲音是正弦波 `A · sin(2π f t + φ)`：

| 符號 | 名稱 | 聽起來 |
| --- | --- | --- |
| `f` | 頻率（Hz，每秒振動幾次） | 音高：越大越高 |
| `A` | 振幅 | 音量：越大越大聲 |
| `φ` | 相位 | 單獨聽不出來；兩個波疊在一起時會影響結果 |

### 2.1 音高與 MIDI 音號

人耳對音高的感覺是**對數**的：頻率變 2 倍 = 高一個八度。一個八度分成 12 個半音，每個半音頻率乘 `2^(1/12) ≈ 1.0595`。

MIDI 音號把鋼琴鍵編號：60 = 中央 C、69 = A4 = 440 Hz。

```python
def midi_to_hz(m):
    return 440.0 * 2.0 ** ((m - 69) / 12.0)
```

| 音 | MIDI | 頻率 |
| --- | --- | --- |
| D1 | 26 | 36.7 Hz |
| D2 | 38 | 73.4 Hz |
| A4 | 69 | 440 Hz |
| D5 | 74 | 587 Hz |
| C7 | 96 | 2093 Hz |

**音分（cent）**：一個半音再分成 100 份，用來表示「差一點點」。`f × 2^(cents/1200)`。7 音分的差距，耳朵聽不出走音，但兩個音疊在一起會有緩慢的起伏（見第 4 節）。

### 2.2 音量與分貝

音量的感覺也是對數的，所以用**分貝**表示：`dB = 20 · log10(振幅)`。

| 振幅 | dBFS（相對滿格） |
| --- | --- |
| 1.0 | 0 dB（滿格，再大就爆音） |
| 0.7 | -3 dB |
| 0.5 | -6 dB |
| 0.1 | -20 dB |

**峰值**看最大的那個取樣，避免爆音；**RMS**（均方根）`sqrt(mean(x²))` 代表平均能量，比較接近「聽起來多大聲」。

## 3. 泛音：為什麼鋼琴和長笛不一樣

只有正弦波的聲音很「單調」，像電子測試音。真實樂器振動時，除了**基頻** f，還會同時發出 2f、3f、4f…… 的**泛音**。各個泛音的強弱比例決定了**音色**。

```python
# pad 的一個音：第 h 個泛音的振幅 = h^(-1.7)
for h in range(1, 9):
    voice += h ** -1.7 * np.sin(2 * np.pi * f * h * t)
```

| 泛音衰減 | 聲音 |
| --- | --- |
| `1/h`（全部泛音） | 鋸齒波：明亮、像銅管 |
| `1/h`（只有奇數泛音） | 方波：空洞、像單簧管 |
| `h^-1.7`（這個專案） | 柔和、像弦樂 pad |
| 只有 h = 1 | 正弦波：純淨、像長笛的高音 |

讓高泛音的強度隨時間慢慢變化（程式裡的 `bright` LFO），聽起來就像濾波器在開合，聲音會「活」起來。

**不是整數倍的泛音**會讓聲音像金屬或鐘。星星的鐘聲用 1、2.76、5.40 倍，是金屬棒振動的近似比例。高泛音衰減得比較快，所以剛敲下去很亮，後面剩下圓潤的基音。

## 4. 拍頻：兩個很接近的音

兩個頻率差一點點的正弦波疊在一起，會一下「同相」變大聲、一下「反相」互相抵消，產生週期性的起伏，這就是**拍頻**：

```
sin(2π f₁ t) + sin(2π f₂ t) = 2 cos(π (f₁ - f₂) t) · sin(π (f₁ + f₂) t)
                               └─ 慢慢變化的音量 ─┘   └─ 平均的音高 ─┘
```

起伏的頻率 = `|f₁ - f₂|`。持續音用 73.42 Hz 和 73.54 Hz，差 0.12 Hz，**每 8.3 秒起伏一次**，像在呼吸。

樂手調音也是用這個方法：兩條弦越接近，「哇哇哇」的拍頻越慢，完全消失就代表調準了。

pad 的三個聲部互相走音 ±7 音分，也是同樣的原理。只是起伏比較快、又有很多泛音，聽起來不是一下一下的起伏，而是一種「寬、厚」的合唱感（合成器裡叫 **detune / unison**）。

## 5. 包絡線：聲音怎麼開始、怎麼結束

一個音突然從 0 跳到滿格，揚聲器會「喀」一聲，因為不連續的跳動包含所有頻率。所以每個音都要乘上一條**包絡線**（envelope），讓音量平滑地變化。

合成器的經典包絡線是 **ADSR**：

```
音量
 │   /\
 │  /  \_______
 │ /           \
 │/             \
 └─A──D───S────R──→ 時間
```

| 階段 | 意思 | pad | 星星 |
| --- | --- | --- | --- |
| Attack | 從 0 升到最大 | 7 ~ 11 秒（慢慢浮現） | 4 毫秒（敲擊） |
| Decay | 降到持續音量 | — | 指數衰減 1.2 ~ 3 秒 |
| Sustain | 按住時的音量 | 和弦持續期間 | — |
| Release | 放開後淡出 | 9 秒 | — |

這個專案的淡入淡出用 `sin²` / `cos²`，曲線的開頭和結尾斜率都是 0，比直線更平滑：

```python
env[:a]  = np.sin(np.linspace(0, np.pi / 2, a)) ** 2   # 淡入
env[-r:] *= np.cos(np.linspace(0, np.pi / 2, r)) ** 2  # 淡出
```

**4 毫秒的 attack** 很快，聽起來像敲擊，又不會產生喀聲（不到 1 毫秒就會開始聽到「喀」）。

## 6. 立體聲：聲音在左邊還是右邊

把同一個聲音以不同音量送到左右聲道，耳朵就會覺得聲音偏向比較大聲的那邊，這叫 **pan（聲像）**。

直覺做法是 `左 = 1 - p、右 = p`，但移到中間時兩邊各 0.5，**總功率只剩一半**，聽起來會變小聲。所以改用**等功率聲像**：

```python
ang = (p + 1) * np.pi / 4      # p = -1（左）~ +1（右）→ 0 ~ π/2
left, right = np.cos(ang), np.sin(ang)   # cos² + sin² = 1，總功率固定
```

## 7. 噪聲與濾波：用 FFT 在頻域做事

**FFT**（快速傅立葉轉換）把一段聲音拆成「每個頻率有多少」（頻譜）。在頻譜上乘一條曲線，再轉回來，就是**濾波**：

```python
spec = np.fft.rfft(x)                        # 時域 → 頻域
freqs = np.fft.rfftfreq(len(x), 1 / SR)      # 每一格的頻率
spec *= 1 / (1 + (freqs / 1500) ** 2)        # 低通：1500 Hz 以上慢慢變小
y = np.fft.irfft(spec, n=len(x))             # 頻域 → 時域
```

**風聲**是反過來做的：直接在頻域造一個「某個頻帶有能量、相位隨機」的頻譜，轉回時域就是帶通噪聲。白噪聲（所有頻率一樣強）像收音機的沙沙聲；只留 350 Hz 附近的頻帶，就變成低沉的「呼——」。

| 濾波器 | 留下 | 聽起來 |
| --- | --- | --- |
| 低通（low-pass） | 低頻 | 悶、遠、在水裡 |
| 高通（high-pass） | 高頻 | 薄、像電話 |
| 帶通（band-pass） | 某一段 | 像風、像對著瓶口吹氣 |

最後的混音也做了一個 30 Hz 的高通：喇叭放不出這麼低的聲音，但它還是會佔掉峰值空間。

## 8. 殘響：用摺積模擬空間

在大房間裡拍一下手，會聽到一連串越來越小的回聲。這串回聲叫做**脈衝響應**（impulse response，IR），它記錄了「一個瞬間的聲音，在這個空間裡會變成什麼樣子」。

任何聲音在這個空間裡的效果 = 原音和 IR 的**摺積**（convolution）：每個取樣都觸發一份 IR，全部疊起來。

```
原音：  |    |  |
IR：    |\
        | \___
結果：  |\   |\ |\
        | \__|_\|_\___
```

這個專案的 IR 是**指數衰減的噪聲**（真實大廳的 IR 也很像這樣）：

```python
tau = REVERB_SECONDS / 6.91           # RT60：衰減 60 dB 的時間；e^-6.91 = 0.001 = -60 dB
ir = noise * np.exp(-t / tau)
```

高頻部分衰減得比較快（空氣和牆面會吸收高頻），所以回聲越後面越暗，聽起來比較自然。左右聲道用不同的噪聲，回聲就會有包圍感。

直接計算摺積要 `N × IR 長度` 次乘法（30 億次以上），用 FFT 的話只要「頻譜相乘」：

```python
y = np.fft.irfft(np.fft.rfft(x) * np.fft.rfft(ir, n=len(x)), n=len(x))
```

**乾 / 濕**（dry / wet）：原音叫 dry，殘響叫 wet。wet 比例越高，聲音越遠、越朦朧。星星的 wet 是 0.85，所以聽起來像從遠處傳來。

## 9. 無縫循環：把時間接成一個環

FFT 有一個特性：它把訊號當作**無限重複**的。所以用 FFT 做的濾波和殘響，結尾的回聲會「繞」回開頭，這叫**循環摺積**。一般情況下這是要避免的副作用，但對循環音樂來說剛好是我們要的。

其他部分也照「環」的想法處理：

| 聲音 | 問題 | 解法 |
| --- | --- | --- |
| 一個音超過結尾 | 被切掉 → 喀聲 | 超過的部分加回開頭（`add_circular`） |
| 一直響的正弦波 | 結尾相位 ≠ 開頭 → 喀聲 | 頻率取 `k / L`，L 秒內剛好轉 k 圈（`loop_freq`） |
| 殘響、濾波 | 回聲在結尾被切掉 | FFT 循環摺積 |
| 噪聲 | 結尾和開頭不連續 | 直接在頻域產生（本身就是週期的） |

頻率取整數圈的誤差很小：L = 96 秒時，頻率最多只差 `1 / 96 / 2 ≈ 0.005 Hz`，耳朵完全聽不出來。

## 10. Unity 的聲音系統

| 元件 / 資產 | 角色 | 比喻 |
| --- | --- | --- |
| `AudioClip` | 聲音檔（WAV、OGG、MP3） | 一張 CD |
| `AudioSource` | 播放聲音的元件，掛在物件上 | 喇叭 |
| `AudioListener` | 收音的元件，通常在 Main Camera 上，**場景裡只能有一個** | 耳朵 |

```csharp
var source = gameObject.AddComponent<AudioSource>();
source.clip = Resources.Load<AudioClip>("Audio/SpaceAmbience");
source.loop = true;          // 循環
source.spatialBlend = 0f;    // 0 = 2D（音量固定），1 = 3D（離 Listener 越遠越小聲、有左右方位）
source.volume = 0.35f;
source.Play();
```

### 常用屬性與方法

| 名稱 | 作用 |
| --- | --- |
| `Play()` / `Stop()` / `Pause()` / `UnPause()` | 播放控制 |
| `PlayOneShot(clip, volume)` | 播一次音效，不影響目前的 clip（適合按鈕聲、碰撞聲） |
| `volume` | 0 ~ 1 |
| `pitch` | 播放速度兼音高：2 = 快一倍、高八度 |
| `loop` | 播完從頭開始 |
| `spatialBlend` | 2D ↔ 3D |
| `time` | 目前播到第幾秒 |
| `AudioListener.volume` | 全域音量（所有聲音） |
| `AudioListener.pause` | 全域暫停 |

**音樂不受 `Time.timeScale` 影響**：遊戲暫停時音樂會繼續播放。如果想讓音樂跟著暫停，要自己呼叫 `Pause()`，或設 `AudioListener.pause = true`。

### 匯入設定（點選音檔後的 Inspector）

| 設定 | 選項 | 這個專案 |
| --- | --- | --- |
| Load Type | Decompress On Load：載入時解壓，最省 CPU、最吃記憶體<br>Compressed In Memory：記憶體裡保持壓縮，播放時解壓<br>Streaming：邊讀邊播，最省記憶體 | Streaming（長的音樂適合） |
| Compression Format | PCM：不壓縮<br>Vorbis：有損壓縮，約 1/10 大小<br>ADPCM：輕度壓縮，適合短音效 | Vorbis，品質 0.7 |
| Normalize | 把峰值拉到滿格 | 關（產生器已經控制好音量） |
| Force To Mono | 合成單聲道 | 關（要保留立體聲） |

## 12. 自己動手試試

每次改完執行 `python Assets/Docs/space_music_gen.py`，雙擊 WAV 就能聽，回到 Unity 也會自動重新匯入。

1. **聽拍頻**：把 `DRONE_BEAT_HZ` 改成 `1.0`，持續音會變成每秒「哇」一次；改成 `0` 起伏就消失。
2. **換音色**：`PAD_BRIGHTNESS` 改成 `1.0`（很亮、像鋸齒波）和 `3.0`（很暗、接近正弦波），比較兩者的差別。
3. **走音合唱**：`PAD_DETUNE_CENTS` 改成 `0`（很「細」）和 `25`（明顯走音），找出你覺得最舒服的值。
4. **改和弦**：把 `CHORDS` 改成大調的 `[[38,45,54,57,64],[43,50,55,59,62],[45,52,57,61,64],[38,45,54,57,64]]`（D – G – A – D），聽聽看氣氛差多少。星星原本用小調的五聲音階，裡面的 F、C 會和大調的 F♯、C♯ 衝突，所以要一起把 `STAR_MIDI` 改成 D 大調五聲音階 `[74,76,78,81,83,86,88,90,93,95]`（D E F♯ A B）。
5. **空間大小**：`REVERB_SECONDS` 改成 `1`（小房間）和 `15`（大教堂）。
6. **滿天星星**：`STAR_INTERVAL` 改成 `0.5`。因為只用五聲音階，再密也不會刺耳。
7. **看頻譜圖**：每次產生後打開 `Temp/StarrySkyPreview/space_music_preview.png`，找出每一層聲音在圖上的位置：最下面的亮帶是持續音，中間每 24 秒換一次的橫條是和弦，上方的短線是星星，紫色的雲是風聲。
8. **Unity 裡試試 `pitch`**：Play 中在 Inspector 找到 Simulator 上的 Audio Source，把 Pitch 改成 0.5，整首歌會變慢、低一個八度，聽起來更深邃。

## 13. Unity 即時合成：OnAudioFilterRead

（第 13 節是為了 [行星之歌說明.md](行星之歌說明.md) 加的，接著第 10 節的 Unity 聲音系統。）

前面的音樂都是**先算好、存成檔案**再播放。如果聲音要跟著遊戲狀態即時變化，例如行星的音高跟著角速度走，就要在 Unity 裡**邊播邊算**。

### 13.1 音訊執行緒

Unity 的聲音是由獨立的**音訊執行緒**處理的。它每隔一小段時間（例如 1024 個取樣，48 kHz 時約 21 毫秒）向每個 AudioSource 要下一段聲音。在 MonoBehaviour 裡寫一個 `OnAudioFilterRead`，就可以在這個時候改寫（或直接產生）那段聲音：

```csharp
[RequireComponent(typeof(AudioSource))]
public class SineTest : MonoBehaviour
{
    public float frequency = 440f;   // 主執行緒可以改
    double phase;
    int sampleRate;

    void Start() => sampleRate = AudioSettings.outputSampleRate;   // 先在主執行緒讀好

    // data：交錯的取樣 L R L R …；channels：聲道數
    void OnAudioFilterRead(float[] data, int channels)
    {
        double step = 2 * System.Math.PI * frequency / sampleRate;
        for (int i = 0; i < data.Length; i += channels)
        {
            phase += step;
            float x = 0.2f * (float)System.Math.Sin(phase);
            for (int c = 0; c < channels; c++) data[i + c] += x;
        }
        phase %= 2 * System.Math.PI;
    }
}
```

| 規則 | 原因 |
| --- | --- |
| 必須和**正在播放**的 AudioSource 在同一個物件上 | 濾波器是插在那個 AudioSource 的處理鏈上的。沒有音檔時，放一段無聲的循環 `AudioClip.Create(...)` 當載體 |
| **不能呼叫 Unity API**（Transform、Camera、`Time`、`Debug.Log` 都不行） | 它不是在主執行緒上跑的。需要的資料先在 `Update` 算好，存進欄位 |
| 要**快**、不能配置記憶體 | 音訊執行緒必須準時交出聲音，來不及就會爆音或斷音 |
| 用**累加相位**，不要用 `sin(2π f t)` | 頻率改變時 `f × t` 會突然跳一大段 → 喀聲；累加相位 `phase += 2π f / SR` 永遠是連續的 |
| 參數要**平滑** | `Update` 每幀才改一次目標值；如果直接套用，音量和音高會一階一階地跳。在每個 buffer 裡從舊值線性內插到新值 |

### 13.2 主執行緒和音訊執行緒怎麼分工

```
主執行緒 Update（60 次/秒）               音訊執行緒 OnAudioFilterRead（約 47 次/秒）
  讀 CelestialBody 位置、速度               cur = cur + (target - cur) × k    ← 一階平滑
  讀 Camera                                 每個取樣：相位 += 2π f / SR
  → targetFreq[i]、targetGain[i]  ───────→  data[s] += sin(相位) × 音量
```

`float` 的讀寫是原子的，所以一邊寫、一邊讀不會讀到「寫到一半」的數字；最多晚一個 buffer，耳朵聽不出來。

### 13.3 一階平滑（指數趨近）

```csharp
float k = 1f - Mathf.Exp(-bufferSeconds / tau);   // tau = 平滑時間常數
cur += (target - cur) * k;
```

每次往目標走剩下距離的一部分，經過 `tau` 秒大約走完 63%，`3 × tau` 秒走完 95%。和 buffer 長短無關，所以在不同的取樣率、buffer 大小下聽起來都一樣。這個公式在遊戲裡很常用，相機跟隨、數值顯示的平滑也可以用它。

### 13.4 自己動手試試

1. 在 Play 中把 Planet Song 的 **Glide Seconds** 改成 0.01 和 1，跟隨水星並加速到 `5`，比較音高變化的感覺。
2. **Brightness** 改成 0，聽純正弦波；改成 1，聽有泛音的版本（第 3 節）。
3. 把 **Spread** 改成 1（真實比例），聽聽看哪些行星消失了。答案是外行星：它們的頻率會低於 20 Hz，人耳聽不到。
4. 打開 **Snap To Scale**，再按 `M` 打開或關掉背景音樂，比較和諧程度。
